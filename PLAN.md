# STDOUT — план личного сайта

Личная «свалка инфы»: заметки, короткие посты, проекты, ссылки.
Референс по стилю: https://www.life-exe.com/ (берём только визуальный стиль, контент свой).

## Решения (итог прожарки)

| Вопрос | Решение |
|---|---|
| Название | **STDOUT** — логотип `STDOUT■` с оранжевым квадратом-курсором |
| Контент | 4 типа: `note` (статья), `post` (короткая мысль), `project`, `link` |
| Структура | **Одна лента**, одна папка `.md`, поле `type` в frontmatter, фильтр по типу |
| Добавление | Markdown-файлы + `git push` → автодеплой. Без админки и БД |
| Движок | **Astro** (content collections, подсветка кода, 0 JS по умолчанию) |
| Язык | **Только английский** (UI и посты). Без i18n |
| Тема | **Только тёмная**. Без переключателя |
| Картинки | Без обложек в v1. Картинки только внутри постов |
| Фичи v1 | Теги (+ страница тега), RSS |
| Не в v1 | Поиск, комментарии, i18n, светлая тема, обложки/halftone |
| Главная | Хиро (крупное STDOUT + строка о себе + соцсети) → свежие записи |
| Хостинг | **GitHub Pages**, деплой через GitHub Actions по push |

## Стиль (из референса)
- Фон почти чёрный (~#141414), текст белый, акцент оранжевый (~#F04E0F)
- Огромный жирный uppercase-гротеск в заголовках, моно-шрифт для мета/кода
- Брутальные карточки: тонкие рамки, без скруглений и теней
- Плашки-бейджи (`NOTE`, `POST`, `PROJECT`, `LINK`) в оранжевой рамке
- Адаптив под телефон

## Модель контента
`src/content/entries/<slug>.md`:
```yaml
---
title: "..."          # для post можно пропустить
type: note | post | project | link
date: 2026-11-15
tags: [astro, cpp]
url: https://...      # для link (обязательно) и project (опционально)
repo: https://github.com/...  # для project, опционально
description: "..."    # кратко для карточки и RSS
draft: false
---
```

## Страницы
- `/` — хиро + последние записи
- `/feed` — вся лента, фильтр по типу (`/feed/note`, `/feed/post`, …)
- `/e/<slug>` — запись (для `link` карточка ведёт наружу, страница тоже есть)
- `/tags/<tag>` — записи по тегу
- `/about` — кратко о себе
- `/rss.xml`

## Этапы и как проверяем
1. **Каркас Astro + git** → `npm run dev` открывается, `npm run build` без ошибок
2. **Стили и layout** (шапка, футер, токены цветов/шрифтов) → визуально сверить с референсом в браузере, проверить ширину 375px
3. **Коллекция контента + схема** → по 1 тестовой записи каждого типа; невалидный frontmatter роняет билд
4. **Главная, лента, фильтры, страница записи** → все 4 типа отображаются корректно, ссылки работают
5. **Теги + RSS** → страница тега показывает нужные записи, `rss.xml` валиден
6. **Деплой на GitHub Pages** → push в main → сайт доступен по `<ник>.github.io`
